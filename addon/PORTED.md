# Ported code

| File here | Source | Changes |
|---|---|---|
| `shaders/pack.hlsl` | Voxel Photonics, *VLED Volume Capture* Unreal plugin (`VLEDUnrealPlugin.uplugin` version 1.0, `EngineVersion` 5.8.0), `Shaders/Private/VoxelStudioPack.usf`. The copy read was in `Downloads\VLEDUnrealPlugin` on Machine C, 2026-10-10 | `#include "/Engine/Public/Platform.ush"` removed. The loose parameters gathered into `cbuffer PackConstants : register(b0)` and the resources given explicit registers. Long comments trimmed. **Arithmetic unchanged but for one addition, marked PERSPECTIVE** (2026-10-11): with perspective lenses each pixel is placed along its own ray (scene depth is view-space z) and its position stored packed 11:11:10 in the depth row, because UE4 drops dynamic lights and shadows from orthographic captures (The Ascent: 4.8 times darker than a lens, same frame) |
| `shaders/pack.hlsl`, a second addition | - | **UNITY, marked in the file** (2026-10-12), compiled only into the `DEPTH_BUFFER` build (`obj/pack_depth_cs.h`): depth from the face's own depth buffer, reversed-Z device depth turned back into distance by the near and far planes `rig/unity` set, and rows read bottom-up, as Unity stores render textures on D3D11. A shipped Unity game cannot compile the shader that would put depth in the colour's alpha. The Unreal build is unchanged |
| `shaders/pack.hlsl`, a third addition | - | **SURFACE_COLOUR, marked in the file** (2026-10-12), compiled only into the `SURFACE_COLOUR` build (`obj/pack_surface_cs.h`): each face's base-colour capture (the surfaces' own colours, no lights) read at the same texel and the lit colour mixed over it by `Lighting`. The lit capture still gives depth. MK1's lighting spans more than 20 stops, more than any one exposure fits on the display |
| `shaders/pack.hlsl` and `shaders/compact.hlsl`, REDENGINE3 | - | **Marked REDENGINE3 in both** (2026-10-13), for The Witcher 3's swept camera (`sweep_red3.hpp`): the camera's place from the centre is a vector (`CamRel`; the rigs' own cameras give -CamD x Fwd, as before), the colour may be the game's finished picture (`DisplayColour`: metered and exposed in linear light, then encoded again; not tone-mapped), a frame too wide is read every `SrcStep`-th texel, and the compact pass takes any face height (`ActiveRows`) |
| `shaders/pack.hlsl`, REDENGINE4 | - | **Marked REDENGINE4** (2026-10-14), for Cyberpunk 2077's render-to-texture cameras (`red4_rtt.hpp`): a face's colour may be a few texels larger than its depth (`SrcSize`, in what was a pad), read at the nearest texel; 0 leaves the pass as it was |
| `shaders/pack.hlsl`, COLOUR RANGE | - | **Marked COLOUR RANGE in the file** (2026-10-12): after the tone map (and the surface colour), each colour is scaled whole so its brightness (its brightest channel) runs from `ColorFloor` to `ColorCeiling` - the band a Voxon display shows well. Hue and saturation are kept; black becomes grey at the floor. The app used to apply this per channel on the CPU, which lifted every channel to the floor and greyed out saturated colours |
| `shaders/pack.hlsl` and `shaders/compact.hlsl`, LOOK and PLAYER LOOK | - | **Marked LOOK and PLAYER LOOK in both** (2026-10-15): the pack pass applies a gamma and a saturation after the exposure (0 and 0 change nothing). With `PlayerMask` set it reads each face's player capture (t3: the player alone, scene depth in red), takes a pixel whose depth is the player's for the player's, gives it the player's own exposure, gamma and saturation, and sets bit 24 of its colour word. UNITY (the `DEPTH_BUFFER` build): t3 is the player camera's depth buffer, turned into distance by the face's planes
before the comparison. The compact pass reads that flag and draws the player's voxel `PlayerDepth` deep, copies a display cell apart along the face's line of sight (`PlayerDir`, `CellStep`), each merged as any voxel. Off, both passes are as they were |
| `shaders/pack.hlsl`, SOLID SURFACES | - | **Marked SOLID SURFACES in the file** (2026-10-15): with `PlayerMask` bit 1 the pack pass reads each face's solid capture (t4: the chosen see-through surfaces alone, made opaque, their depth in cm; Unity: that camera's depth buffer, turned into cm by the face's planes) and takes its depth wherever it is nearer than the face's own, or the face saw nothing. With bit 2 (2026-10-16) only where the face's glow capture (t5: the same surfaces as the game draws them, in alpha the light they let through) says they are at least `SolidOpacity` opaque; the player capture's depth in front of the scene too. Off, the pass is as it was |
| `shaders/pack.hlsl` and `shaders/compact.hlsl`, SCALE | - | **Marked SCALE in both** (2026-10-12): the perspective positions are packed over each of the rig's axes' own range (`QuantX`, `QuantY`, `QuantZ`), and the compact pass scales each axis back into the display's box (`ScaleX/Y/Z`) before the rig's turn, so a game's world can be squashed or stretched per axis. The VX2-XL flag now follows the display (square side faces on a VX2) |
| `shaders/compact.hlsl` | the same plugin, `Shaders/Private/VoxelStudioCompact.usf` | the same treatment, as `cbuffer CompactConstants`. **Two additions, marked in the file** (2026-10-11): DISPLAY writes display units with the rig's yaw turned back (and, turning with the player, a quarter turn more: `DisplayTurnDeg`), where the plugin wrote metres and the CPU transformed every voxel; MERGE keeps one voxel per display cell (`mergePerUnit`, 56 on a VX2-XL), because the display adds light and the plugin kept every pixel of every face - 21% of a volume was doubled where faces overlap, 81% at six faces of 1024 px. The plugin's own reconstruction is unchanged; a third addition, PERSPECTIVE, reads the pack pass's packed positions in its place when the rig uses lenses |
| The face table, the per-face constants, the tilt and window maths, the auto-exposure smoothing | the same plugin, `VledRenderVolume.cpp` (`FaceTable`, `CamAxisSign`, `SetupCameras`, `DispatchCaptureFrame`, `DispatchPackCS`) | re-expressed in `voxon_capture_ue.cpp` and `../VoxonTapUE/lua/Scripts/rig.lua`. **One deliberate difference: `CamDist`**, the camera's stand-off. The plugin uses `4 × Bound`; here it comes from `camDist` in `voxon_capture_ue.ini`, so the cameras can stand on the volume's edge and cut the level away (`the-ascent/PLAN.md`, Phase 3) |
